# my-new-project
サービス名：ReciScan AI (レシスキャン AI)

〜スマホひとつで、レシートを即座に資産データへ〜

1. サービス概要

  - どんなサービスか：カメラ撮影からAI解析、データ保存、CSV出力までをシームレスに行う、超軽量なレシート解析特化型Webアプリケーションです。
  - 解決する課題：確定申告等のための「溜まったレシートの手入力作業」の苦痛を、受け取ったその場での「撮影→自動解析」という習慣に変えることで解決します。

2. このアイデアはどこから生まれたか

2-1. きっかけとなった体験・感情

確定申告の時期や経費精算の際、財布の中に溜まったレシートを1枚ずつ見てExcelに打ち込む作業に強い苦痛を感じていました。「今、この瞬間にスマホで撮ってデータ化できれば、後でまとめてやる絶望感から解放されるのに」という強い違和感がきっかけです。

2-2. なぜそれが「気になった」のか

私は「単純な反復作業」による時間の損失を極端に嫌う性格だからです。テクノロジー（AI）がこれだけ進歩しているのに、依然として多くの人が手入力を行っている現状を、もっとスマートな体験（UX）に書き換えたいと考えました。

3. 課題の整理

3-1. 表に見えている困りごと

  - レシートの内容を手入力するのが面倒で、つい溜めてしまう。
  - 外出先でレシートをもらった際、すぐに記録する手段が定着しない。

3-2. 本当に解決したい課題は何か

  - なぜ手入力が面倒か？ → 小さい文字を読み取り、複数の項目（日付・店名・金額）を打ち分けるのがストレスだから。
  - なぜストレスか？ → 集中力を要する作業であり、スマホの小さな画面での入力ミスも怖いから。
  - なぜ入力ミスが怖いか？ → 最終的な会計データとしての信頼性が損なわれるから。

→ 本当に解決したい課題： 「データ入力という非創造的な作業への心理的ハードルを極限まで下げ、"撮るだけ"という快感に変えること」

4. 想定ユーザーについて

4-1. 想定しているユーザー

ターゲット： 「確定申告を自分で行っている、移動の多いフリーランス」

  - 理由：
    普段からPCを持ち歩くが、レシートはその場でスマホで処理したい。多機能なクラウド会計ソフトの「画面の複雑さ」や「機能の重さ」を嫌い、シンプルなツールを好む傾向があるため。
  - 年齢： 20代〜40代
  - 生活状況： カフェやコワーキングスペースでの移動が多く、経費が発生しやすい。

4-2. 自分とユーザーの距離

  - 自分自身： 開発者自身が最もこのツールを必要としている「最初のユーザー」であるため、ユーザーの不満点を誰よりも理解しています。

4-3. 実際に使われる可能性について

  - 誰が： 会計ソフトへの入力前の「一時的なデータ化」を行いたい層。
  - 代わり： スマホのメモ帳、または高機能なクラウド会計アプリ。
  - 置き換える理由： 既存の会計アプリは多機能ゆえに起動や画面遷移が遅い。本アプリは「レシートの解析と保存」に特化しており、ログイン後の撮影までの導線が圧倒的に短い。

4-4. ユーザーがサービスを導入して利用するまでのイメージ

1.  アカウント作成 / ログインを行う。
2.  カメラでレシートを撮影（または画像アップロード）。
3.  サーバー経由でAIが自動で項目（日付・店名・金額など）を抽出し、DBに保存。
4.  結果をその場で確認・修正。
5.  溜まったデータは週末にCSV出力して、普段のメイン会計ソフトやExcelに流し込む。

5. 既存サービス・競合調査

5-1. 似たサービスの調査

  - サービス名： 各種クラウド会計ソフト（freee, マネーフォワード等）のレシート撮影機能、レシート読取り（レシーピー！）
  - できること： OCRによる読み取り、仕訳の自動作成。

5-2. それでも自分が作りたい理由

既存サービスは「会計処理全体」をカバーするため、機能が肥大化しており、単に「レシートを素早くテキスト化してストックしておきたい」という用途にはオーバースペックです。また、レシート読取りは、読取り後のデータが、SaaS上に保存され、データ出力がありません。また、広告も邪魔です。私は**「余計な機能がなく、開いてすぐに撮影・保存ができる『入り口』に特化したツール」**が欲しいと考えました。

5-3. 差別化を「体験価値」で表現する

  - 差別化ポイント： 「多機能さを捨てた圧倒的な身軽さ。レシートを撮ってCSVにするまでの『最短経路』を提供する特化型体験」

6. このサービスで提供したい価値

6-1. ユーザーの変化

  - 行動： レシートを溜め込まず、その場ですぐにデータ化する習慣がつく。
  - 気持ち： 経費精算という「重荷」が、AIによる「自動検知」という楽しい体験に変わる。

6-2. 価値を一文で表す

「このサービスは、入力作業を嫌うフリーランスが、カメラをかざすだけで正確な会計用CSVを手に入れられるサービス」

6-3. プライバシーとセキュリティの明記

・画像データの扱い： 解析のため、レシート画像はバックエンドサーバーを経由してGoogle Gemini APIへ送信されます。解析後は速やかに破棄し、サーバー内には解析結果のテキストデータのみを保存します。（※Gemini APIの利用規約に準拠）
・認証と保護： ユーザーデータはセキュアなデータベースで隔離・管理され、ログインした本人のみがアクセス可能です。

7. このアプリで実現すること

MVPで作る機能

  - ユーザー認証（サインアップ、ログイン）
  - カメラ撮影 / 画像アップロード機能
  - Gemini API連携によるレシート解析（バックエンドで処理）
  - **解析結果の確認および手動修正（編集）機能**
  - 解析結果のデータベース保存と履歴一覧表示
  - CSVエクスポート（Excel対応BOM付き）


本リリース時の追加機能（MVP以降の展開）

  - データ活用： 蓄積されたデータから「月々の経費傾向」を分析する簡単なダッシュボード機能。
  - 他サービス連携： 出力CSVのフォーマットを、主要な会計ソフトのインポート形式に最適化するプリセット機能。

9. 技術スタック

9-1. 使用予定の技術

  - フロントエンド： React + Vite , Tailwind CSS
  - バックエンド：  Python (FastAPI)
  - データベース： PostgreSQL
  - AI： Gemini API (バックエンドからコール)
  - インフラ（デプロイ先）：
    フロントエンド：Vercel
    バックエンド：Render.com

9-2. 技術選定の比較検討

| 候補          | 採用/不採用 | 理由                                      |
| ----------- | ------ | --------------------------------------- |
| React + Vite | 採用     | JSXのコンパイルやコンポーネント分割を活用し、保守性の高いSPA（シングルページアプリケーション）を構築するため。 |
| Next.js     | 不採用    | バックエンドにPython (FastAPI) を採用し、フロント側と責務を完全に分離する構成とするため。|
| Python (FastAPI) | 採用 | カリキュラムで学習した技術であり、型安全な設計やpytest等を用いたユニットテストとの親和性が高く、堅牢なAPIを構築できるため。また、AI（Gemini API）連携の実装が容易なため。 |
| PostgreSQL  | 採用     | 会計データという構造化されたデータを扱うため、信頼性の高いリレーショナルデータベースを採用。 |
| Gemini API  | 採用     | 複雑なレシートフォーマットでも、高い精度で必要な項目をJSONとして抽出できるため。 |

9-3. キャッチアップ不足の懸念

バックエンドからGemini APIへ画像を送信してJSONを受け取る一連のデータフローの連携に苦戦する可能性があります。まずは「固定の画像をアップロードしてテキストを返す」最小のAPIから実装を開始します。

Reactについてのキャッチアップについて：
1. コンポーネント設計（共通化と分割）
  「1つのファイルに全部書く」ことをせず、部品ごとにファイルを分けて、それらを組み合わせて画面を作る。
  「ボタン」「入力フォーム」「履歴の1行」などを別ファイル（コンポーネント）に分ける。
  親から子へデータを渡す「Props（プロップス）」を利用。
  HistoryListコンポーネントの中に、HistoryItem（1件分の表示）を並べるような設計をする。
2. フォームの実装（状態の同期）
  ユーザーが入力した文字を、リアルタイムでReactの変数（State）に保存し、送信ボタンを押したときにその内容を取り出せる。
  onChangeイベントを使って、入力された文字を即座にStateに反映できる。
  onSubmitでページがリロードされるのを防ぐ。
  AIが解析した「金額：1,200円」という結果を、ユーザーが「1,250円」に修正して保存ボタンを押す、という一連の流れが作れる。
3. 状態管理（useState）
  「今、画面はどういう状況か？」を変数で管理し、それに応じて表示を切り替える。
  「読み込み中（Loading）」や「エラー発生」などのフラグをStateで管理し、表示を切り替える。
  isLoadingがtrueなら「解析中...」というぐるぐる（スピナー）を出し、終わったら解析結果を出す、という制御ができる。
4. API連携（fetch / async / await）
  バックエンドにデータを送り、返ってきた結果を受け取って画面に表示できる。
  fetch（またはaxios）を使って外部にリクエストを送れる。
  async / await を使って、返事を待ってから次の処理をする「非同期処理」を利用。
  通信エラーが起きた時、try...catch を利用。
  Geminiが解析したJSONデータ（日付や金額）を受け取って、入力フォームに自動セットできる。
5. 副作用の制御（useEffect）
  「画面が開いた瞬間」や「特定のデータが変わった時」だけ実行したい処理にする。
  アプリを開いた瞬間に、LocalStorageやDBから過去の履歴データを自動で読み込む処理にする。
