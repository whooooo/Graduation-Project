# my-new-project
サービス名：ReciScan AI (レシスキャン AI)

〜ブラウザひとつで、レシートを即座に資産データへ〜

1. サービス概要

  - どんなサービスか：カメラ撮影からAI解析、CSV出力までをブラウザ1枚（サーバー不要）で完結させる、超軽量なレシート解析特化型ツールです。
  - 解決する課題：確定申告等のための「溜まったレシートの手入力作業」の苦痛を、受け取ったその場での「撮影→自動解析」という習慣に変えることで解決します。

2. このアイデアはどこから生まれたか

2-1. きっかけとなった体験・感情

確定申告の時期や経費精算の際、財布の中に溜まったレシートを1枚ずつ見てExcelに打ち込む作業に強い苦痛を感じていました。「今、この瞬間にスマホで撮ってデータ化できれば、後でまとめてやる絶望感から解放されるのに」という強い違和感がきっかけです。

2-2. なぜそれが「気になった」のか

私は「単純な反復作業」による時間の損失を極端に嫌う性格だからです。テクノロジー（AI）がこれだけ進歩しているのに、依然として多くの人が手入力を行っている現状を、もっとスマートな体験（UX）に書き換えたいと考えました。

3. 課題の整理

3-1. 表に見えている困りごと

  - レシートの内容を手入力するのが面倒で、つい溜めてしまう。
  - 外出先でレシートをもらった際、すぐに記録する手段が（既存アプリのログイン等が手間で）定着しない。

3-2. 本当に解決したい課題は何か

  - なぜ手入力が面倒か？ → 小さい文字を読み取り、複数の項目（日付・店名・金額）を打ち分けるのがストレスだから。
  - なぜストレスか？ → 集中力を要する作業であり、スマホの小さな画面での入力ミスも怖いから。
  - なぜ入力ミスが怖いか？ → 最終的な会計データとしての信頼性が損なわれるから。

→ 本当に解決したい課題： 「データ入力という非創造的な作業への心理的ハードルを極限まで下げ、"撮るだけ"という快感に変えること」

4. 想定ユーザーについて

4-1. 想定しているユーザー

ターゲット： 「確定申告を自分で行っている、移動の多いフリーランスエンジニア」

  - 理由：
    普段からPCを持ち歩くが、レシートはその場でスマホで処理したい。多機能な会計ソフトの「重さ」や「ログインの壁」を嫌い、シンプルなツールを好む傾向があるため。

  - 年齢： 20代〜40代

  - 生活状況： カフェやコワーキングスペースでの移動が多く、経費が発生しやすい。

  - 環境設定： PCとスマホの両方を使うが、入力はスマホのカメラを起点にしたい。

4-2. 自分とユーザーの距離

  - 自分自身： 開発者自身が最もこのツールを必要としている「最初のユーザー」であるため、ユーザーの不満点を誰よりも理解しています。

4-3. 実際に使われる可能性について

  - 誰が： 会計ソフトへの入力前の「一時的なデータ化」を行いたい層。
  - 場面： レシートを受け取った直後、または週末のカフェ。
  - 代わり： スマホのメモ帳、または高機能なクラウド会計アプリ、OCRツール、無料のレシート読み取りアプリ。
  - 置き換える理由： 会計アプリは起動が重く、ログインが必要。本アプリはURLを開くだけで即撮影・解析が始まり、圧倒的に速い。

4-4. ユーザーがサービスを導入して利用するまでのイメージ

1.  ブラウザでURLを開く（ブックマークから即起動）。
2.  【初回のみ】Gemini APIキーを設定（LocalStorageにのみ保存）。
3.  カメラでレシートを撮影。AIが自動で項目を抽出。
4.  結果をその場で確認・修正。
5.  溜まったデータは週末にCSV出力して、普段の会計ソフトやExcelに流し込む。

5. 既存サービス・競合調査

5-1. 似たサービスの調査

  - サービス名： 各種クラウド会計ソフト（freee, マネーフォワード等）のレシート撮影機能、レシーピ！
  - できること： OCRによる読み取り、仕訳の自動作成。

5-2. それでも自分が作りたい理由

既存サービスは「アカウント作成」と「月額課金」が前提であり、またデータが常にクラウドサーバーに保存されます。私は**「自分のAPIキーを使い、データはLocalStorageのみで完結する、完全にプライベートでオープンなツール」**が欲しいと考えました。

5-3. 差別化を「体験価値」で表現する

  - 差別化ポイント： 「ログイン不要・サーバー保存なし。URLを開いた1秒後にはシャッターを切れる、URLを開いてからシャッターを切るまでの速度を最優先の爆速レシート解析体験」

6. このサービスで提供したい価値

6-1. ユーザーの変化

  - 行動： レシートを溜め込まず、その場、あるいはその日のうちにデータ化する習慣がつく。
  - 気持ち： 経費精算という「重荷」が、AIによる「自動検知」という楽しい体験に変わる。

6-2. 価値を一文で表す

「このサービスは、入力作業を嫌う個人事業主が、カメラをかざすだけで正確な会計用CSVを手に入れられるサービス」

6-3. プライバシーとセキュリティの明記

・Geminiへの送信： 解析のため、レシート画像はGoogle Gemini APIへ送信されます。
・LocalStorageの利用： 履歴データおよびAPIキーは、ユーザーのブラウザ（LocalStorage）にのみ保持されます。
・リスクと対策： APIキーはブラウザに保持されるため、端末紛失時のリスクはあります。利用者にAPIキーの利用制限（API Restrictions）設定を推奨することでリスクを最小化します。


7. このアプリで実現すること

MVPで作る機能

  - APIキー設定フォーム： ブラウザ上で入力し、LocalStorageに保存する機能
  - Gemini API連携によるレシート解析（日付、店名、金額、科目、備考）
  - カメラ機能（リアルタイムプレビュー、ピント検出、自動撮影）
  - LocalStorageによる履歴一覧
  - CSVエクスポート（Excel対応BOM付き）



8. このアプリの懸念点とその対策

懸念点①：APIキーのセキュリティ

  - 問題： ユーザーが入力したAPIキーが漏洩するリスク。
  - 対策：
    本アプリは、APIキーはブラウザのLocalStorageにのみ保存します。Google Cloud側での制限設定手順をガイドとして提供します。

9. 今後の展開・発展の方向性

  - データ活用： 蓄積されたデータから「月々の経費傾向」を分析するダッシュボード機能。
  - 他サービス連携： 出力CSVのフォーマットを、主要な会計ソフト（freee, 弥生等）のインポート形式に最適化するプリセット選択機能。

10. 技術スタック

10-1. 使用予定の技術

  - フレームワーク： React (CDN)
  - UI/アイコン： Tailwind CSS, Phosphor Icons
  - AI： Gemini API
  - データ保存： LocalStorage

10-2. 技術選定の比較検討

| 候補          | 採用/不採用 | 理由                                      |
| ----------- | ------ | --------------------------------------- |
| Next.js     | 不採用    | 「1枚のHTMLで完結するポータビリティ」を優先するため。           |
| React (CDN) | 採用     | 複雑なDOM操作を宣言的に記述しつつ、環境構築不要で動作させるため。      |
| Gemini API  | 採用     | 無料枠があり、画像認識能力が極めて高く、JSONレスポンスの制御が容易なため。 |

10-3. キャッチアップ不足の懸念

ReactをCDN経由で利用するため、ビルド環境（Vite等）のトラブルは回避できますが、Gemini
APIのレスポンス安定性やプロンプト調整に時間を要すると予想されます。まずは「確実にJSONが返ってくる」プロンプトを固定することに注力します。
